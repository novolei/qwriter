# Qwriter 产品目标与验收路线

更新：2026-09-07。目标是 Windows / macOS 上的本地优先 AI 写作工作室。以 Typora 的流畅写作体验为参照，在可控 AI 协作、跨文稿创作与媒体工作流上形成优势。美感和“超越”需要持续的任务测试与用户评价，不能仅凭截图宣告完成。

## 体验约束

- 文字始终是主角。纸白、灰绿、细边框和克制动效延续现有设计；工具按需要展开。
- 常用操作同时具有可发现的鼠标入口和键盘路径。少操作、明确反馈，保留用户的上下文和焦点。
- 显示偏好不改变 Markdown。内容修改可撤销或有可恢复历史；AI 先建议、后审阅，再由用户采纳。
- 参考文稿、模型目的地、正在执行的步骤清晰可见。不把配置与工程细节推给普通写作者。
- 中英双语、浅深主题、900×640 小窗口与大屏验证是每轮功能验收的一部分；减少动态效果偏好始终有效。

## 接续开发顺序

### 1. 可靠的模型与任务管理

- 系统凭据、模型池、配置备份 / 导入已实现，详见 [模型管理系统](MODEL-SYSTEM.md)。后续补充模型角色分工与上下文预算。
- 可恢复的任务记录：保存用户明确需要保留的目标、参考快照、结果与执行摘要；密钥不入库，重启后不得自动重发计费请求。
- 模型能力检测与引导：区分普通文字、工具调用与视觉模型；服务不支持某能力时给出可操作的替代入口。
- 真机模型矩阵：DeepSeek 官方 OpenAI 兼容 API 已实测；接续验证 Ollama / LM Studio 各至少一个工具模型及真实 Anthropic 服务。

验收：重启不用重复配置，错误不会丢失已完成草稿，停止与重试无重复写入，任务可以明确恢复或另存。

### 2. 文件夹工作区与 Git 闭环

- 文稿与实际 `.md` 文件建立明确绑定；原子保存、文件变更监听、外部修改冲突审阅。
- 从现有 SQLite 文稿库向文件夹导出 / 迁移时保留可验证备份和恢复入口。
- Git 分支、远程同步、凭据、冲突解决逐步加入；复用 git2，保留逐文件差异与明确的提交 / 同步动作。

验收：从外部编辑器修改同一文件不会被静默覆盖；文稿、磁盘和 Git 状态一致；失败可恢复。

### 3. 视觉与 ComfyUI 媒体工作流

- 选择图片作为视觉模型输入，显示文件、大小与发送目的地；区分图片附件与文字参考。
- ComfyUI 工作流模板、参数面板、任务队列、真实进度与取消；服务重连后查询任务实际状态。
- 解析图片 / 视频输出，预览、选择落盘、插入文稿，管理项目相对路径与素材引用。

验收：图片理解、图片生成、视频生成各有一条可复现的端到端流程；失败不显示成功占位结果，输出素材可离线找回。

### 4. 长文与 Markdown 完整性

- 建立 CommonMark / GFM、数学、脚注、front matter、HTML 的真实往返语料库，逐步从源码保护走向完整编辑支持。
- 文稿目录、标签、最近访问、回收站、模板和写作目标；以实际日常任务决定信息层级。
- 大文稿与大型文稿库性能基线：启动、输入、搜索、保存、内存与资源体积；逐篇保存与增量索引。
- 输出与交付：打印 / PDF、排版模板、目录 / 图片资源的可移植导出。

验收：不同模式切换与导入导出不损坏内容；长文输入无明显阻塞，搜索与保存耗时有测量记录。

### 5. 跨平台发行与可访问性

- Windows 安装包、macOS arm64 / x64 构建、签名 / 公证和升级迁移。
- Windows WebView2 与 macOS WKWebView 真机键盘、输入法、缩放、屏幕阅读器与高对比度测试。
- 与 Typora 对照完成“导入—查找—修改—AI 协作—审阅—导出”任务，记录操作数量、错误恢复和用户偏好。

验收：两平台实际安装、升级、卸载流程通过；用户能够仅用键盘完成核心任务；设计改进有用户任务证据。

写作 Agent 限定于本次附加的文稿、图片和明确允许的记忆范围，不含 MCP、联网检索、任意文件访问或终端执行。桌面任务结果保留最近 100 次，可恢复草稿继续创作；尚无完整事件检查点重放。单次最多 12 个文稿参考（界面最多 10 篇额外文稿，加当前文稿与上一份草稿），单篇 128 KB，总计 512 KB；最多 4 张图片。模型自身上下文窗口仍可能更小。

源码编辑使用 CodeMirror 的撤销历史，正文使用 ProseMirror 的撤销历史；两种模式没有统一的跨模式撤销栈。复杂语法目前仍走源码保护。Git 仍管理用户选择的文件夹和导出副本，尚未与 SQLite 双向同步。ComfyUI 仍是 JSON 工作流接口。Windows 构建不代表 macOS 已完成实机验证。
