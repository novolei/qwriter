# 知识检索与 DeepSeek 适配验收

日期：2026-09-07；Windows、本地浏览器预览、原生 Rust 服务测试。没有访问真实供应商 API，没有使用或记录用户密钥。

## 浏览器操作

- 新建独立「验收样例 · 森林写作札记」，包含中文段落、ATX 标题、表情字符和英文段落。原有 5 篇文稿均未修改。
- 检索「光影 森林」「concrete sentences」；结果提供章节、行号和版本，英文词项命中对应英文段落。
- 打开来源，原片段高亮；来源编辑后保存，检索结果显示 revision 2，重新打开来源定位正常。
- 900×640、1440×900、1920×1080；浅色中文、深色英文。浮窗始终 600px 目标宽、受视口约束，未出现横向溢出；900×640 外框约 600×601.6。
- 关闭来源返回原检索按钮；从来源进入编辑时焦点进入标题输入；再次打开知识库聚焦搜索。
- 归档验收条目，再检索不返回该素材。验证完成后恢复中文、浅色与默认浏览器尺寸。
- 双视图并发复测：第一个视图保留 revision 4 检索结果，第二个视图编辑为 revision 5；打开旧结果显示快照，切换当前版本显示新的标题、来源和 revision 5，不显示旧行号。第二个视图归档后，第一个视图只能查看已有快照，当前版本与编辑按钮不再出现。验收素材最终保持归档。

## 发现、修复与复测

1. 初版按每个空行分块，短标题会成为孤立命中卡片。调整为普通段落累积到约 300 字符再在空行切分，章节边界仍保留；浏览器及 Unicode/围栏测试已复测。
2. 嵌套来源窗口关闭时，shared Modal 会把焦点放到父浮窗第一个按钮。改为优先返回仍在父浮窗中的实际触发按钮；补分层 Escape 和焦点恢复测试，实际浏览器复测通过。
3. 知识库首次打开时，组件 effect 早于 portal 内容创建，搜索框未获焦点。使用 shared Modal 的 data-autofocus 协议，实际中英界面复测通过。
4. 开发服务器曾缓存未包含新样式的聚合 CSS，导致来源图标纵向排列、原生黄色 mark。之后又复现 Agent 面板模块缺少导出；HTTP 响应的 source map 明确显示空源文件，磁盘源码却包含完整导出。定位为 Windows 写入中间状态被监听器读取。Vite 改为 awaitWriteFinish（200ms 稳定窗口、50ms 检查间隔）。服务重启稳定后，使用临时模块执行“完整内容→空文件 80ms→完整新内容”的 HTTP 探针，确认写入期间保留旧完整模块，稳定后提供新导出；探针文件已删除。真实浏览器重新进入 Agent 和知识库成功，新验收视图控制台无错误。生产构建和最终截图包含完整样式。
5. 查看已更新的来源时，原版提示仍描述旧片段。当前版本视图改为显示新的标题、来源、修订号与专用说明，隐藏旧章节和行号。补齐双语回归断言，并按上面的双视图流程复测。
