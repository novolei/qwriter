# Qwriter · 写作流程与模型管理验收

日期：2026-09-07；环境：Windows、Tauri 2、当前浏览器预览。

## 本轮设计结果

以现有的纸白、灰绿、羽毛标识和衬线文稿为基准，补充可直接使用的写作与模型管理流程。供应商维护地址、协议与凭据，模型池维护模型 ID、别名、启用状态与当前选择；同一供应商的多个模型共享凭据。高级连接参数默认折叠，日常切换留在写作面板。

| 原先的任务障碍 | 改进与验证 |
| --- | --- |
| 每份模型配置重复填写服务地址与密钥 | 供应商与模型池分层；发现目录后多选入池，也可手动添加；保留多账户连接 |
| 切换模型需要进入设置 | 独立分组搜索器，方向键 / 回车选择；默认聚焦当前模型，Escape 关闭并恢复焦点 |
| “获取模型”容易被理解为 Agent 一定可用 | 分开目录鉴权测试与实际工具调用验证；分别展示数量、延迟、验证时间和错误 |
| 重启后密钥需要再次填写 | 桌面版可显式保存到系统凭据库；普通配置持久化不含密钥，浏览器明确提示原生能力边界 |
| 文稿与常用操作入口分散 | Ctrl/⌘ P 搜索正文、标题、最近文稿和 11 项操作；统一弹窗与键盘路径 |
| 富文本缺少完整的文内定位与替换入口 | Ctrl/⌘ F 高亮、逐项跳转、单次 / 全部替换；一个事务可撤销 |
| 源码是基础文本输入 | CodeMirror Markdown 编辑、语法高亮、查找 / 正则 / 全词与独立撤销历史 |
| AI 缺少明确的任务执行过程 | 写作 Agent 显示参考、工具步骤、停止、草稿建议与审阅；显式采用或另存 |

新增供应商不会改变当前写作模型。任务执行时快捷切换禁用，已启动任务使用配置快照；设置修改只影响后续任务。重复点击与迟到响应有保护，切换 A → B → A 后也不会接纳第一次 A 的旧结果。修改服务来源不会将原密钥带到新来源。

## 交互和响应式检查

- 在 900×640、1600×900 与 2560×1440 检查布局，无页面横向溢出。小窗口收起文稿栏，保留重新打开的入口。
- 常规桌面设置外框为 600×840；900×640 下约 600×601。模型连接与外观字体切页保持一致外框，标题 / 关闭入口固定，内容独立滚动。
- 实际通过界面建立 DeepSeek 官方连接，添加 Flash / Pro 两个带别名的模型，保留原有 Ollama；搜索、键盘选择和页面重载后的当前模型恢复均通过。
- 中英文、晨光 / 深色主题、模型池分组与表单焦点状态均检查。用户自定义供应商 / 模型名称不翻译。
- Ctrl/⌘ P → 查找、Ctrl/⌘ F → 高亮、关闭查找、打开 Agent 与模型切换的最终重载检查未产生新的控制台错误。修复工具栏与查找栏重复 React key 的问题。
- 浏览器验证未修改用户文稿；仍为原有 4 篇文稿，当前文稿 346 字符，保留“感谢有你！”。

## 自动化与真实服务验证

- `npm run check`：架构与文件规模、格式、严格 TypeScript、46 项前端测试、Rust fmt / Clippy、28 项 Rust 常规测试和 Specta 类型一致性检查通过。
- `npm run desktop:build`：Windows 调试桌面程序构建通过，产物 `src-tauri/target/debug/qwriter.exe`。构建仍提示部分前端分块超过 500 KB，后续性能预算包含此项。
- DeepSeek 官方实测：目录返回 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp`、`deepseek-v4-pro`，本次目录延迟 111 ms；实际 Agent 能力验证通过，本次耗时 1546 ms。这些是单次观测，不是性能承诺。
- 写作任务实际执行 `search_documents → read_document → propose_draft` 三轮工具调用，产出通过内容断言的 93 字中文草稿。仅使用测试素材，没有发送用户文稿。
- Windows Credential Manager 实测：独立临时条目保存、读取、删除、确认不存在全部通过。测试条目已删除。
- 上述真实服务 / 系统凭据测试平时标记 ignored，已分别显式执行通过；用户临时 API Key 只进入测试进程环境，未持久化到项目、日志、模型池或系统凭据库。
