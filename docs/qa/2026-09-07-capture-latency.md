# 截图快捷键响应优化 · 2026-09-07

## 定位与测量

Windows 本机，主屏 3840 × 2160。使用显式启用的 `capture_latency` Rust 测试，将捕获、窗口枚举和 PNG 编码分别计时。测试不保存截图、不输出窗口名称或像素，不参与默认 CI。

```powershell
cargo test --manifest-path src-tauri/Cargo.toml capture_latency -- --ignored --nocapture
```

| 阶段 | 原调试构建，3 次 | 优化依赖后的调试构建，3 次 |
| --- | --- | --- |
| 屏幕捕获 | 346 / 351 / 332 ms | 86 / 64 / 63 ms |
| 窗口枚举 | 1 / 0 / 1 ms | 1 / 0 / 0 ms |
| PNG 编码 | 2485 / 2475 / 2372 ms（自适应过滤） | 345 / 328 / 329 ms（固定 Sub 过滤） |

原流程还无条件等待 180 ms，并在第一次调用时才创建 WebView。捕获与编码阶段合计从约 2.8 秒降至约 0.4 秒。桌面内容在两批测量间有所变化；这些是阶段耗时样本，不是严格同帧基准，也不是按键到首帧的端到端测量。磁盘写入、IPC、图片解码和 UI 绘制时间不在表内。

## 实施

- 仅优化开发构建中的 xcap、image 和 PNG 压缩依赖，保留业务代码的调试配置。
- 临时截图采用 Fast + Sub 无损 PNG，避免逐行尝试多个过滤器；最终导出策略不变。全通道往返测试覆盖 RGB 和 alpha，保护原像素取色。
- 启动后预建隐藏捕捉 WebView，后台加载标注组件。失败保留按需创建路径；不采集屏幕或剪贴板，不在后台启动 OCR。
- 主应用按需加载，截图窗口无需加载文稿编辑器的完整应用模块。
- 仅实际隐藏 Qwriter 窗口时等待桌面合成，保留原有 180 ms。从其他软件或最小化状态截图时不再固定等待。Windows 原生回归发现 60 ms 会截入隐藏动画，已修复为保留动画等待。
- 明确刷新截图缓存的缓冲写入，传播磁盘失败。

预热会增加少量常驻 WebView 内存；固定过滤可能产生稍大的临时 PNG。没有降采样、JPEG 有损压缩或放宽截图窗口权限。

## 验证范围

编码回归测试和完整质量检查覆盖协议、i18n、架构与已有截图交互测试。原生构建与快捷键回归在 Windows 执行；macOS 权限、合成动画与性能仍需真机验证。手动性能测试需主动运行，不能据此宣称所有设备均达到相同速度。

- `npm run check` 与 `npm run desktop:build` 均通过；90 个前端测试、34 个 Rust 测试通过，4 个需显式运行的原生测试默认忽略。
- 重新启动最终构建后验证主窗口首次 Ctrl+Alt+S：选区正常显示，180 ms 合成等待消除了主窗口残影；Escape 关闭截图，主窗口重新可见。
- 从资源管理器两次呼出同一个捕捉浮窗，读取新屏幕；单击识别 1268 × 1386 的窗口选区，取消后重新呼出不残留该选区。取色放大镜正常显示。
- 本轮未用精确计时器记录原生 UI 首帧，未宣称端到端 0.4 秒；浏览器预览页已关闭，界面回归使用新构建的原生 WebView。
